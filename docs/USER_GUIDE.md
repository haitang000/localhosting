## 📊 资源统计

### 在哪里？
点击顶部导航栏的 **"统计"** 按钮，或访问 `#/stats`

### 能做什么？

#### 👤 普通用户视图
- **我的资源使用**：查看你的实例消耗的 CPU、内存、网络流量
- **实例详情**：快速查看所有运行中实例的资源配置
- **时间范围**：切换 1h / 24h / 7d / 30d 查看不同时段数据

#### 👨‍💼 管理员视图（额外功能）
- **全局统计**：查看所有用户的总体资源使用情况
- **用户排行**：按 CPU/内存/网络消耗查看用户排名
- **活跃监控**：实时查看活跃实例数和用户数

### 使用示例

**场景 1：查看本月资源消耗**
1. 进入统计页面
2. 点击 "30d" 按钮
3. 查看平均和峰值数据

**场景 2：管理员优化资源分配**
1. 查看全局统计
2. 查看用户排行榜
3. 识别资源使用高的用户
4. 合理调整资源配额

## ⏰ 定时任务

### 在哪里？
点击顶部导航栏的 **"任务"** 按钮，或访问 `#/tasks`

### 能做什么？

- ✅ 定时启动实例（如每天早上9点）
- ✅ 定时停止实例（如每晚6点节省资源）
- ✅ 定时重启实例（如每周日凌晨）
- ✅ 定时备份实例（如每天凌晨2点）

### 创建任务步骤

1. 点击 **"新建任务"** 按钮
2. 选择要操作的实例
3. 选择操作类型（启动/停止/重启/备份）
4. 输入 Cron 表达式，或点击快捷按钮：
   - **每天 9:00** → `0 9 * * *`
   - **工作日 9:00** → `0 9 * * 1-5`
   - **每 30 分钟** → `*/30 * * * *`
   - **每周日 0:00** → `0 0 * * 0`
5. 点击 **"保存"**

### Cron 语法说明

格式：`分 时 日 月 周`

```
┌───── 分钟 (0 - 59)
│ ┌───── 小时 (0 - 23)
│ │ ┌───── 日 (1 - 31)
│ │ │ ┌───── 月 (1 - 12)
│ │ │ │ ┌───── 星期 (0 - 6，0 = 周日)
│ │ │ │ │
* * * * *
```

**常用示例：**
- `0 9 * * *` - 每天上午 9:00
- `0 9 * * 1-5` - 工作日上午 9:00
- `*/30 * * * *` - 每 30 分钟
- `0 */2 * * *` - 每 2 小时
- `0 0 1 * *` - 每月 1 号午夜
- `0 0 * * 0` - 每周日午夜
- `30 18 * * 1-5` - 工作日下午 6:30

### 管理任务

- **编辑任务**：点击任务卡片上的 ✏️ 编辑按钮
- **暂停任务**：点击 ⏸ 暂停按钮（可重新启用）
- **删除任务**：点击 🗑️ 删除按钮（需确认）

### 使用示例

**场景 1：开发环境自动管理**
```
任务 1：工作日早上 9:00 启动开发服务器
任务 2：工作日晚上 6:00 停止开发服务器
```
→ 节省夜间和周末的资源消耗

**场景 2：定期备份重要数据**
```
任务：每天凌晨 2:00 备份数据库实例
```
→ 自动保护数据安全

**场景 3：服务定期重启**
```
任务：每周日凌晨 3:00 重启应用服务器
```
→ 防止内存泄漏，保持服务健康

## 📦 备份管理

### 在哪里？
点击顶部导航栏的 **"备份"** 按钮，或访问 `#/backups`

### 能做什么？

- ✅ 导出实例配置和数据
- ✅ 下载备份到本地
- ✅ 从 docker-compose.yml 导入配置
- ✅ 管理备份文件

### 导出实例

1. 点击 **"导出实例"** 按钮
2. 选择要导出的实例
3. 点击 **"开始导出"**
4. 等待导出完成（可能需要几分钟）
5. 导出完成后会出现在备份列表中

**导出内容包括：**
- `docker-compose.yml` - 完整的容器配置
- `metadata.json` - 元数据信息
- `volumes/` - 数据卷内容（如果有）

### 下载备份

1. 在备份列表中找到需要的备份
2. 点击 **"下载"** 按钮
3. 保存 `.tar.gz` 文件到本地

### 导入配置

1. 点击 **"导入配置"** 按钮
2. 输入新实例的名称
3. 粘贴 `docker-compose.yml` 内容
4. 点击 **"解析配置"**
5. 系统会解析并显示配置信息
6. 前往 "新建实例" 页面手动创建实例

**支持的 docker-compose.yml 格式：**
```yaml
version: '3.8'

services:
  myapp:
    image: nginx:latest
    container_name: myapp
    restart: unless-stopped
    environment:
      - API_KEY=secret123
      - MODE=production
    ports:
      - "20001:80/tcp"
    volumes:
      - ./volumes/volume_0:/data
    mem_limit: 512m
    cpus: 0.5
```

### 删除备份

1. 找到要删除的备份
2. 点击 **"删除"** 按钮
3. 确认删除操作

⚠️ **注意**：删除备份是永久操作，无法恢复！

### 使用示例

**场景 1：测试环境复制到生产**
1. 导出测试环境实例
2. 下载备份文件
3. 在生产服务器上导入配置
4. 创建新实例

**场景 2：灾难恢复**
1. 使用定时任务每天自动备份
2. 实例出现问题时
3. 从最近的备份恢复配置
4. 快速重建实例

**场景 3：跨面板迁移**
1. 在旧面板导出实例
2. 下载备份文件
3. 在新面板导入配置
4. 重新创建实例

```
工作日：
  - 9:00 自动启动开发服务器
  - 18:00 自动停止开发服务器

周末：
  - 保持停止状态

→ 每周节省 48 小时的资源消耗

### 技巧 4：定期维护
```
每周日凌晨：
  1. 备份所有重要实例
  2. 重启长期运行的服务
  3. 清理不需要的旧备份

## ⚠️ 注意事项

### 资源统计
- 数据每 5 分钟采集一次
- 仅采集运行中的实例
- 历史数据保留 30 天
- 停止的实例不会出现在统计中

### 定时任务
- 任务精确到分钟级别
- 暂停的任务不会执行
- 实例不存在时任务会跳过
- 备份任务会消耗磁盘空间

### 备份管理
- 导出大容量实例可能耗时较长
- 定时备份 30 天后自动删除
- 手动备份需要手动删除
- 备份文件占用服务器磁盘空间

## 🔧 故障排查

### 问题 1：统计数据不更新
**原因**：stats-collector 未启动或实例未运行
**解决**：
1. 检查面板日志：`grep "stats.collect" server.log`
2. 确认实例状态为 "运行中"
3. 等待下一次采集（最多 5 分钟）

### 问题 2：定时任务不执行
**原因**：cron 表达式错误或实例不存在
**解决**：
1. 检查 cron 表达式是否正确
2. 确认实例存在且可操作
3. 查看任务的 "下次运行时间"
4. 检查任务状态是否为 "暂停"

### 问题 3：导出失败
**原因**：磁盘空间不足或权限问题
**解决**：
1. 检查服务器磁盘空间
2. 查看 `data/backups/` 目录权限
3. 查看面板日志了解详细错误

### 问题 4：导入配置无法创建实例
**原因**：导入只是解析配置，不会自动创建
**解决**：
导入后需要手动前往 "新建实例" 页面创建实例
