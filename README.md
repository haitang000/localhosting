# localhosting

一个自托管的 Docker 容器面板：别人注册账号后在网页上挑镜像、填参数、点一下就有了自己的服务，
面板自动分配对外端口，配合内网穿透即可让服务在公网可达。

**资源分配靠「券」**：管理员生成实例资源券时就写死这张券给多少内存、多少 CPU、几个对外端口；
用户拿券去创建实例，跑什么镜像自己挑，但资源用量由券说了算，改不动。

**创建走审批**：用户提交的是一份「申请」，面板先把主机端口预留好但不碰 Docker；
管理员在待审批队列里看到要转发哪个端口，手动把内网穿透配好，填上用户实际访问的地址，
点放行之后容器才真正被创建和启动。

- **审批制**：用户的实例都要管理员放行，穿透由管理员手动配、地址手动填（管理员自己开的不排队）
- **拖放部署静态网页**：把 `index.html` 或整个网页文件夹拖进面板就上线，不建容器、不占端口、
  不用等审批，同样要花一张券，但一个站点只按 **0.1 核 · 32 MB** 记账
- **闲时休眠**：没人访问就把容器停掉，有人连上来面板再自动把它拉起来，冷启动一两秒
- **开放注册**：默认任何人都能注册，靠面板自绘的算术验证码（零依赖、不连外部服务）加两层
  IP 限速挡机器人；`OPEN_REGISTRATION=false` 可切回邀请码制
- **注册即送一张静态网页券**：新用户一进来就能把自己的网页发出去，不用先找管理员要券；
  这张券**只能发静态网页**，跑容器还是得单独要
- **实例资源券**：注册开放不等于资源开放 —— 创建实例 / 发布站点仍要花一张券，
  内存/CPU/端口额度写死在券上
- **模板库 + 自定义镜像**：51 个开箱即用模板，分 Web / 建站 / 开发 / 数据库 / 工具 / 媒体 / AI / 游戏 八类
  （Nginx、Caddy、WordPress、Halo、code-server、Jupyter、PostgreSQL、MySQL、Redis、MongoDB、ClickHouse、
  Grafana、Jellyfin、Open WebUI、Minecraft、Factorio 等），可按券或按账号放开任意镜像
- **端口池自动分配**，一段连续端口整体转发出去就完事
- **实例管理**：启动/停止/重启/删除、实时日志、资源监控
- **容器内的实时终端**：网页版 `docker exec -it`，会话活在服务端（刷新回来接着用）。
  彩色输出、`vim`/`htop` 这类全屏程序、Tab 补全、断线自动接回、密码提示自动掩码，
  手机上另有一条 Esc / Ctrl 按键条 —— 终端是手写的，没有 xterm.js
- **容器文件管理**：在网页上翻容器里的目录、在线改配置文件、拖文件进去、把文件或整个目录拉下来 ——
  不用 `docker cp`，也不用镜像里装 tar / unzip / vim
- 零原生依赖（SQLite 用 Node 内置的 `node:sqlite`），只有 `express` 和 `dockerode` 两个包

## 快速开始

前置条件：Node.js ≥ 22.5、Docker（Desktop 或 dockerd）正在运行。

```bash
npm install
```

```bash
cp .env.example .env
```

```bash
npm start
```

首次启动会在控制台打印初始管理员的用户名和随机密码（也可以先在 `.env` 里写死 `ADMIN_PASSWORD`）。
打开 http://localhost:8099 登录即可。

> Windows 上如果控制台中文变乱码，先执行 `chcp 65001` 再启动，或者用 Windows Terminal。

## 注册：默认开放，验证码 + 限速兜底

登录页的「注册」标签任何人都能用，不需要邀请码。挡机器人的是多道闸：

1. **行为分析** —— 面板在浏览器里记录鼠标/触摸轨迹和打字节奏（弯曲度、方向角
   方差、速度波动、末尾减速、打字节拍），服务端打分；通过线每次请求随机浮动，
   伪造轨迹没法精确命中。行为落进「不确定区」时会弹一张**图片回正**挑战：SVG
   按随机角度旋转后发给客户端，旋转量**烘焙进几何坐标**——标记里找不到答案，
   只能真的去看图把方向拖正（答错可微调重试几次，角度容差默认 ±10°）。
2. **工作量证明 (PoW)** —— 服务端给一个随机前缀 + 难度，浏览器在后台算出一个
   nonce 使 `sha256(前缀+nonce)` 前 N 位为 0（默认 18 位，对真人约零点几秒，
   零交互）。这是唯一没法「伪造」的一层：脚本每拿一个验证 token 都得花真算力，
   失败多的 IP 难度还会自动上调最高 4 位。
3. **一次性 token + IP 绑定 + 时间约束** —— 验证通过签发的一次性 token 5 分钟
   有效，绑死签发的 IP，跨 IP 使用直接作废；签发→求解→使用三环各有最低间隔
   （秒答 = 脚本）。
4. **失败退避** —— 同一 IP 注册连续失败 5 次后开始指数级锁定（30 秒起，最长 15 分钟），
   和登录共用同一套机制。
5. **成功限速** —— 同一 IP 每小时最多注册成功 `REGISTER_IP_PER_HOUR` 个账号（默认 3），
   刷验证码本身也有频率上限，每 IP 未解的挑战图最多 3 张（防并行穷举）。

整套验证码零依赖、不连任何外部服务，离线也能用。相关开关见 `.env.example` 里的
`CAPTCHA_*`（`CAPTCHA_ENABLED` 可整体关闭、`CAPTCHA_POW_BITS` 调难度等）。

想回到邀请码制，设 `OPEN_REGISTRATION=false`：登录页变回「邀请码注册」，验证码消失，
注册邀请码重新成为唯一入口。面板架在反向代理 / 内网穿透后面时记得开 `TRUST_PROXY=1`，
否则所有人共享代理的 IP，限速会把大家一起锁住。

**面板名称**（登录页、顶栏、浏览器标签上显示的名字）默认 `localhosting`，由
`PANEL_NAME` 环境变量播种；之后在 **管理后台 → 总览 → 品牌设置** 里随时改，
改完立即生效、不用重启。同卡还有 **主题色**（`PANEL_COLOR` 播种，默认
`#006fee`）：logo 和整套强调色都由它派生，改完立刻应用，不用重启。

注册开放**不等于**资源开放：新账号进来只是能看，创建实例、发布站点仍然一张资源券一次，
额度全在券上（见下一节）。

## 用户协议：注册、登录前必须同意

登录和注册表单上都有一个必选的「我已阅读并同意《用户协议》」勾选框，点开是弹窗，
也可以直接访问 `/terms` 独立页（这个地址可以发给别人看）。不勾选，表单交不上去；
就算绕过页面直接调接口，后端也会拒绝——提交里必须带上当前协议的版本号才放行。

- **正文只有一份**，在 `src/terms.js` 里，弹窗和 `/terms` 页渲染的是同一段 HTML。
  默认文本是为这个面板量身写的（资源券、审批、休眠、磁盘限额、审计日志都有对应条款），
  部署前请过一遍，按自己的情况改。
- **改完正文记得把 `TERMS_VERSION` 拨到新日期**：版本号变了，所有用户下次登录时
  重新阅读并勾选一次，旧标签页里没刷新的表单会被要求刷新重读，而不是替人同意新版。
  注意这道门只拦登录：**已经登录的人在会话过期前（`SESSION_TTL_DAYS`，默认 14 天）
  不会被要求重新同意**。想让新版立刻对所有人生效，拨完版本号顺手清一次会话表
  （`sqlite3 data/panel.db "DELETE FROM sessions"`，或让大家重新登录）。
- **同意留痕**：每个账号最近同意的版本和时间记在 `users` 表
  （`terms_agreed_version` / `terms_agreed_at`），完整历史在审计日志里
  （`user.agree_terms`），谁在什么时候同意了哪一版都查得到。
- 自己搭着玩不想要这道门，设 `TERMS_REQUIRED=false` 整体关闭：勾选框消失，
  接口也不再校验。

## 邀请码 = 两种东西

管理后台的 **邀请码** 页里可以生成两类码，都支持设置可用次数和有效期：

| 类型 | 作用 | 携带的额度 |
| --- | --- | --- |
| **注册邀请码** | 仅 `OPEN_REGISTRATION=false` 时需要：对方在登录页切到「邀请码注册」自助开通账号 | 无 |
| **实例资源券** | 用户每创建一个实例、或发布一个静态站点必须花一张 | 内存 MB、CPU 核数、对外端口数、是否允许自定义镜像、**实例有效天数** |

资源券还分「用途」：默认的 **建实例 / 发网页都行**，和只能拿去发静态网页的
**静态网页专用券**（端口恒为 0，额度就是 `SITE_CPUS` / `SITE_MEMORY_MB`，默认 0.1 核 · 32 MB）。
拿静态网页券去新建实例，第一步就会被挡下来并告诉用户去哪用它。

**每个新注册的账号会自动收到一张静态网页券**（`WELCOME_VOUCHER=true`，默认开）：
注册成功当场弹出券号、直接落到「静态站点」页面的输入框里，用户不用先找管理员要券
就能把第一个网页发出去。要跑容器的话仍然得向你要一张真正的资源券 —— 开放注册
因此不等于开放算力，最多是开放了一个网页目录。券号在「账号 → 面板送我的券」里永远找得回来。

典型流程：

1. （邀请码制下）管理后台 → 邀请码 → 类型选「注册邀请码」→ 生成 → 发给对方，对方注册账号。
2. 管理后台 → 邀请码 → 类型选「实例资源券」→ 填 `1024 MB / 1 核 / 2 端口`、可用次数 `3` → 生成 →
   发给对方，对方就能开 3 个这个规格的实例。
3. 对方在「新建实例」页分四步走：先粘贴资源券（立刻显示这张券给多少资源、还剩几次），
   再挑模板（券的端口额度不够的模板会直接标出来），然后填参数，最后对着摘要确认提交。
   券上带自定义镜像权限的话，「自定义镜像」卡片也会跟着解锁。

几个约定：

- 实例的内存 / CPU **完全由券决定**，用户在界面上改不了。
- 实例能活多久也写在券上（「实例有效天数」，0 = 永久）。到期后实例会被**封存**，见下一节。
  注意别和券自己的「有效天数」搞混：那是这张券什么时候作废，跟它换出来的机器能跑多久是两件事。
- 静态站点不看券上的数字：不管花的是 32MB 的小券还是 1024MB 的大券，一个站点一律按
  `SITE_CPUS` · `SITE_MEMORY_MB`（默认 0.1 核 · 32 MB）记账 —— 它背后本来就没有容器。
- 模板需要几个对外端口，券的端口额度就至少要给几个，否则申请会被拒绝。
- 默认 **删除实例会把券的次数退回**（`REFUND_INVITE_ON_DELETE=true`），这样用户敢放心重建；
  想让每张券严格一次性，把它改成 `false`。
- 被驳回、或创建过程失败（镜像拉不下来之类）也会自动退回次数。
- 账号那边只保留一个「最多同时运行几个实例」的上限（`DEFAULT_MAX_INSTANCES`），当作兜底。
- 自定义镜像权限可以按券给（只有这张券能用），也可以在用户编辑框里按账号给（这个人一直能用）。

## 积分套餐：管理后台自定义

不开券、纯花积分的用户，在「新建实例」第 1 步按套餐或自定义规格付积分。套餐在
**管理后台 → 套餐** 页维护，不需要改环境变量重启：

- 套餐 = **名称 + 内存 + CPU + 硬盘 + 价格** 的组合，可上架/下架/编辑/删除，改完立即生效。
- 用户选的规格（内存、CPU、硬盘）三样全对上一套上架中的套餐时，按**打包价**收，
  比逐档加配便宜；端口费在打包价之外另算。
- 首次启动（数据库里还没有套餐）时用 `.env` 的 `POINTS_BUNDLES` 播种一次，
  之后以管理后台为准，改环境变量不再生效。
- **硬盘是实例数据卷的配额**：基础价含 `POINTS_INSTANCE_DISK_MB`（默认 2048MB），
  自定义规格按 `POINTS_DISK_STEP_MB` 一档加钱（`POINTS_DISK_STEP_COST`）。
  配额通过 docker StorageOpt 下发（仅部分存储驱动生效），面板另有 diskguard 轮询
  兜底——超量自动停止实例。用资源券开的实例和没有磁盘配额的老实例回退全局
  `DISK_QUOTA_MB`。

## 新用户第一次登录看到什么

上面那套「券 → 申请 → 审批 → 拿地址」的规矩，对你来说是设计，对刚拿到账号的人来说是猜谜。
所以普通用户第一次登录会自动弹一个四页的向导，把这条路讲一遍：面板是干什么的、
资源券为什么改不了额度、点「提交申请」之后为什么要等你、以及只想放个网页的话可以绕开这一切。
向导随时能跳过（右上角 ✕ 或 Esc），第二页还能直接粘一张券进去看额度 —— 只是查询，不花次数。

关掉向导之后，页面顶部会留下一张可折叠的清单，四项做完就自己消失：

| 清单项 | 什么时候自动打勾 |
| --- | --- |
| 账号已开通 | 能登录进来就算 |
| 拿到一张资源券 | 注册时收到了见面礼，或成功查过一张券（向导里或新建实例页都行），或者已经花掉过一张 |
| 上线第一个服务 | 有了第一个实例或静态站点 |
| 拿到可访问的地址 | 实例被放行跑起来了，或者站点已发布 |

关键在于**勾选状态是服务端按 `instances` / `sites` 的真实数据算出来的**，不是「你看过这一页」就算完成。
所以换台机器、换个浏览器，或者根本没看向导直接把实例建好了，进度都对得上。
落在 `users.onboarding_json` 里的只有纯 UI 状态：向导停在第几步、跳过了没有。

其它细节：

- **管理员看不到这套东西** —— 券是你自己发的，「向管理员索取」对你没意义。
- 升级到这个版本时，已经建过实例或站点的老账号一律当作「已完成」，不会被向导拦一下。
- 用户可以在「账号」页点「不再显示」永久关掉，也能在同一张卡片上点「重看一遍向导」再看，
  或者把清单放回页面顶部。
- 静态站点关掉时（`SITES_ENABLED=false`），向导自动变成三页，清单里也不会再提拖网页那条路。

## 审批流程：用户申请，你配穿透

用户点「提交申请」时，面板**不会碰 Docker**，只做三件事：校验资源券、扣一次额度、
从端口池里给它预留好主机端口。剩下的等你处理。

管理后台 → **待审批**，每条申请会列出：

- 谁申请的、跑什么镜像、占多少内存和 CPU、用的哪张券、用户留的说明
- **要转发的主机端口**（已经替它占住了，不会被别人抢走）
- 每个端口一个「对外地址」输入框

你的操作顺序：

1. 照着列出的主机端口，在 frp / cloudflared / 路由器上把穿透配好
   （穿透客户端指向 `BIND_ADDRESS:主机端口`）。
2. 把用户实际要访问的地址填进输入框，比如 `frp.example.com:34567` 或 `status.example.com`。
   留空就用 `PUBLIC_HOST:主机端口` 拼出来的默认值。
3. 点 **「配好了，放行创建」**——这时候才开始拉镜像、建容器、启动，
   用户那边能看到实时进度，完成后实例页显示的就是你填的地址。

不想给就点 **驳回**并写个理由：端口立刻释放、资源券次数退回，
用户在自己的实例页能看到驳回原因。

**你自己开的实例不排队**：审批队列存在的意义是「先把穿透配好，再建容器」，
而配穿透的就是你 —— 让你给自己点一次放行并没有多把一道关。所以管理员提交的实例
直接开始创建，对外地址先留空（显示成 `PUBLIC_HOST:主机端口`），穿透配好之后
到实例页 → 访问地址 → **改对外地址** 填上真实地址即可。这个入口对已经建好的实例
一直可用，穿透改指向了也能跟着改。

券还是要一张 —— 内存 / CPU / 端口只写在券上，没有第二个来源。
不用去邀请码页手填一遍：「新建实例」第 1 步有个 **给自己开一张券**，
按 `.env` 里的默认额度当场发一张一次性的，填好就能往下走。

其它细节：

- 待审批状态下用户不能启停，只能「撤回申请」（同样释放端口、退回券）。
- 面板重启时，如果有实例卡在「已放行但还没建完」，会自动退回待审批队列，重新点一次放行即可。
- 管理后台标签和顶部导航都会显示待审批数量。

## 只是想放个网页：拖进来就完事

**静态站点** 页面上有一个大方框，把 `index.html` 拖进去 —— 或者把整个网页文件夹拖进去 ——
填个站点名，点发布，地址立刻就能访问（券那一栏面板已经替新用户填好了注册时送的那张）：

```
http://<面板地址>/s/<站点名>/
```

这条路不建容器、不领端口、**不用管理员审批**：文件是面板自己存、自己发的，
所以只要面板本身能被访问（你已经为它配好穿透了），站点就能被访问。

- 拖文件夹时最外层目录会被自动剥掉，`我的网页/index.html` 上线后就是 `/index.html`
- 首页认 `index.html`；只有一个 HTML 文件时用它，有好几个又没有 `index.html` 会让你改名
- 放了 `404.html` 就会用它当 404 页
- 隐藏文件、`node_modules`、`.DS_Store` 会被自动忽略
- 想改内容点「重新部署」再拖一次，地址不变；改名会换地址；删除退回资源券
- 默认上限：每人 5 个站点、单站 300 个文件 / 20 MB（`DEFAULT_MAX_SITES`、`SITE_MAX_FILES`、`SITE_MAX_BYTES`）
- 一个站点按 **0.1 核 · 32 MB** 记账（`SITE_CPUS` / `SITE_MEMORY_MB`），站点卡片上直接写着；
  用户花的券再大也是这个数 —— 新用户注册时送的那张券，额度正好就是它

**地址显示成 `localhost` 打不开？** 站点走的是面板自己的端口，所以要告诉面板它在公网上叫什么：
在 `.env` 里设 `PANEL_PUBLIC_URL=http://你的公网地址:8099`（面板端口本身也得先转发出去），
重启后站点地址就变成 `http://你的公网地址:8099/s/<站点名>/`。没设的时候面板启动日志和
静态站点页顶部都会直接提醒。

想给站点用单独的域名，就把那个域名指到面板，然后设 `SITE_PUBLIC_BASE=https://pages.example.com`
（这条要求你自己有反代把 `pages.example.com/<站点名>/` 转到面板的 `/s/<站点名>/`），
面板显示给用户的地址会跟着变。

> **安全提醒**：用户页面和面板在同一个源上，所以面板默认给它们发
> `Content-Security-Policy: sandbox`，把页面关进一个独立源里——它拿不到面板的 Cookie，
> 也调不动面板 API。代价是页面用不了 `localStorage` / `document.cookie`。
> 只有当你把站点放在另一个域名下时，才适合把 `SITE_SANDBOX` 关掉。

## 闲时休眠：没人用就停，有人访问再起

给实例勾上「闲时休眠」之后：

1. 面板盯着容器的网络流量，连续 N 分钟（默认 15，可按实例改）没有任何收发，就 `docker stop` 它 ——
   内存和 CPU 立刻还回去。
2. 容器一停，对外端口就空出来了，**面板马上自己接管这些端口**。
3. 下一个连上来的人，连接会被暂时挂住（对方只是觉得这次有点慢），面板把端口还给 Docker、
   启动容器、等端口就绪，然后把这条连接原样转发进去。实测冷启动 400 毫秒左右，
   同时到达的一批请求（浏览器打开页面时的并发）会一起被挂住、一起放行，不会有人吃到连接拒绝。

要点：

- **只对 TCP 有效**。UDP 服务（Minecraft 的语音、某些游戏服）没法靠连接唤醒，界面上会禁掉这个选项。
- 容器**运行期间面板完全不在链路上**，没有代理开销，速度就是原来的速度。
- 判空闲看的是容器网卡的收发字节数。如果你的服务自己会定时往外发请求（心跳、轮询、拉取更新），
  它就永远不算空闲，也就永远不会休眠。
- 手动「停止」的实例不会被访问唤醒 —— 那是你主动关的。要让它重新待命，点「唤醒」或重新打开休眠开关。
- 面板重启后，休眠中的实例会被重新接管端口（启动日志里能看到 `💤 xxx 处于休眠`）；
  面板没在跑的那段时间里，休眠实例是连不上的。
- 全局开关和默认值在 `.env`：`IDLE_SLEEP`、`IDLE_SLEEP_DEFAULT`、`IDLE_MINUTES`、`SLEEP_CHECK_SECONDS`。

## 实例有效期：到期封存、宽限期、积分续期

休眠管的是「这会儿没人用」，有效期管的是「这台机器该还了」。

**有效天数写在资源券上**（发券时填，0 = 永久）。用户拿券建实例时，天数被抄到实例上——
之后再改这张券，已经建出来的实例不受影响。**计时从管理员放行、开始建容器那一刻起算**，
排队等审批的日子不算进寿命里。

时间一到，面板把这个实例**封存**：

1. 关掉它的控制台会话。
2. 让休眠模块彻底放手——停掉守着的监听端口，之后再有人访问也不会把它唤醒。
3. `docker stop` 容器，状态转为 `archived`。

### 宽限期

封存后数据进入 **`ARCHIVE_RETENTION_DAYS` 天宽限期**（默认 7 天）。宽限期内：

- **容器和数据卷原样保留**在宿主机上，端口分配也保留着。
- 用户可以在实例详情页**下载数据卷**（通过 Docker archive API 打包成 tar）。
- 用户可以用**积分续期**：付一笔积分，把实例重新激活，容器恢复可启动状态。
- 详情页和卡片上会显示「还剩 X 天数据将被永久删除」的倒计时。

### 续期

用户付 `RENEWAL_POINTS_COST` 积分（默认 100）可延长有效期 `RENEWAL_DAYS` 天（默认 7 天）。
这个价格等于积分开基础实例的价格（100 分 / 7 天）。续期在封存宽限期内和活跃到期前都能用。
**管理员续期免费**。

### 宽限期届满

超过宽限期后，面板**自动彻底删除**实例：
- 删除 Docker 容器
- 删除 Docker 数据卷
- 释放宿主机端口
- 清除数据库记录

这个清理过程最佳尽力：即使某一步失败（比如容器已被手动删掉），后面的步骤仍会继续，
记录本身一定会被清掉。

面板每 `EXPIRY_CHECK_SECONDS` 秒（默认 60）同时检查**到期封存**和**宽限期清理**，
并且**启动时先扫一遍**——停机期间跨过的到期或宽限期不会被漏掉。

`.env` 里相关的配置项：

| 变量 | 默认值 | 说明 |
| ---- | ------ | ---- |
| `VOUCHER_DEFAULT_DAYS` | 0 | 发券表单的默认有效天数 |
| `EXPIRY_CHECK_SECONDS` | 60 | 到期 / 清理扫描间隔（秒） |
| `ARCHIVE_RETENTION_DAYS` | 7 | 封存后宽限期（天），0 = 不自动删除 |
| `RENEWAL_POINTS_COST` | 100 | 续期一次（RENEWAL_DAYS 天）所需的积分 |
| `RENEWAL_DAYS` | 7 | 续期一次延长多少天 |

## 实例控制台：网页版的 `docker exec -it`

实例详情页的「控制台」标签在容器里开一个 shell，输出走 SSE、按键走 POST。
**会话活在服务端**：切标签页、刷新、换台设备回来，接的还是同一个 shell —— 工作目录、
环境变量、还在跑的 `pip install` 都在（闲置 `CONSOLE_IDLE_MINUTES` 分钟后才回收）。

终端是手写的，没有 xterm.js —— 全站零依赖零构建，为一个终端破例不值得。它支持的部分：

- **颜色**：16 色 / 256 色 / 24 位真彩，粗体、暗淡、斜体、下划线、反显、删除线。
  16 色那套按明暗主题各配了一份，目标是在面板自己的底色上正文对比度不低于 4.5:1 ——
  标准 ANSI 原色是给纯黑底设计的，直接拿来用的话浅色主题下的黄和青基本看不见。
- **光标定位与滚动区域**，以及**备用屏幕缓冲区**：`vim`、`htop`、`less` 进来时画在自己的一块
  地方，退出后你原来的输出原样还在。
- **回滚的归属**：程序发 `\x1b[2J` 只清它自己那一屏，你之前的输出仍能往上滚；
  只有 `clear` 命令（它发的是 `2J` + `3J`）才连回滚一起清掉。

**两种输入模式**，右上角「直连键盘」切换（选择记在浏览器里）：

| | 逐行模式（默认） | 直连键盘 |
| --- | --- | --- |
| 怎么发 | 输入整行，回车提交 | 每个按键直接变成字节发给容器 |
| Tab 补全 | 做不到（shell 从没见过半行） | 可以 |
| `vim` / `top` / `y-n` 提问 | 进得去，出不来 | 正常用 |
| 中文输入法 | 正常 | 正常（合成期间交给输入法，提交时整段发出） |
| 屏幕阅读器 | 可用 | 方向键被容器吃掉，不可用 |

所以逐行模式是永久保留的默认，不是为了兼容。

几处值得知道的行为：

- **断线自己接回来**。SSE 断的只是浏览器到面板这一段，容器里的 shell 还活着，面板会自动
  重连（退避封顶 6 次，切回前台会立刻试一次）。**「重启会话」是另一回事**：它真的会结束
  这个 shell，所以点它会先问一句。
- **密码提示会被认出来**。输出最后一行像 `Password:` / `[sudo] password for xxx:` 时，输入框
  自动改成掩码，这一行也不会进历史 —— 面板的输入框不是 tty，不这么做的话 `ssh`、`sudo`
  的密码会明明白白躺在框里，回车之后还进历史。
- **分页器默认关掉**。因为给了 TTY，`git log`、`systemctl status`、`man` 会自作主张调 `less`，
  而用户不知道自己进了 less，接着敲的命令全被当成快捷键吃掉。所以会话里预置了
  `PAGER=cat`、`GIT_PAGER=cat`、`LESS=-FRX` 等默认值，`export PAGER=less` 随时能盖掉。
- **粘贴多行会先问一句**，把剪贴板全文给你看清楚再决定是逐行执行还是合并成一行。
- **手机上有一条按键条**（Esc / Ctrl+C / Ctrl+D / Ctrl+Z，直连模式下再加 Tab 和方向键）——
  软键盘上根本没有这些键。它和命令行一起吸底，软键盘弹起来也不会被顶走。
- 屏幕尺寸按盒子实测上报（字符宽度是量出来的，不是猜的），所以 `ls` 的分栏和 `top` 的画面
  跟你看到的框一样大；最大化按钮能把终端撑满整屏。

## 容器文件管理：网页上直接改

实例详情页的「文件」标签就是一个文件管理器，管的是**容器里面**的文件系统：

- 翻目录、看大小和修改时间，面包屑一路点回去；数据卷的挂载点会做成「快速跳转」按钮，
  因为那才是用户自己的数据所在（镜像自带的文件改了，重建容器就没了）
- 点文本文件在弹窗里改完直接存，配置文件不用为了改一行去学 `vi`（见下面「那个编辑器」）
- 拖文件或整个文件夹进去就上传到当前目录（**保留 `.env` 这类点开头的文件**，
  跟静态站点那边故意相反）
- 单个文件原样下载；目录打包成 `.tar` 下载
- 新建文件夹 / 新建空文件、重命名、删除（删除会问一次，容器里没有回收站）

实现上分两条路，各有各的道理：

| 操作 | 走什么 | 为什么 |
| --- | --- | --- |
| 列目录、新建目录、重命名、删除 | `docker exec` | Docker 没有「这个目录里有什么」的 API，只能在容器里跑 `ls`/`mkdir`/`mv`/`rm` |
| 下载、在线打开、上传、保存 | archive 接口（`docker cp` 用的那对） | 不需要镜像里有 shell、tar 或 unzip，字节也不用绕一趟 base64 终端 |

由此带来两条使用限制，界面上都会直说：

- **要浏览就得让容器跑着**，而且镜像里得有 `/bin/sh` —— 和控制台标签一样的要求。
  休眠中的实例会在你打开这个标签时被自动唤醒。
- 目录条目超过 `FILE_MAX_ENTRIES` 就只列前面这些，界面会提示被截断了。

几个容易踩到、这里已经处理掉的点：

- **保存不会把文件改姓**。写回时先读原文件的权限和 uid/gid 再原样带上，
  所以给 postgres / www-data 用的配置文件不会突然变成 root 的；上传的新文件跟着**目标目录**的归属者。
- 文件名里的空格、引号、`;`、`$(id)` 都只是文件名 —— 路径是作为位置参数交给 `sh` 的，不拼进命令字符串。
- 路径里的 `..` 在服务端就地解析，`/data/../../..` 只会得到 `/`，出不了容器（容器边界本身也在那儿兜着）。
- 二进制文件不给编辑器打开，直接转成下载；超过 `FILE_EDIT_MAX_BYTES` 的文本只读，
  免得保存时把后半截截掉。
- 软链接在列表里有标记，指向目录的可以点进去；直接下载/编辑链接本身会告诉你它指向哪。

### 那个编辑器

`public/editor.js`。底子仍然是一个 `<textarea>` —— 光标、输入法、选区、撤销栈都交回给浏览器，
这些正是自己写编辑器最容易做砸的地方；其余部分围着它搭：

- **行号栏**跟着换行走。开了自动换行以后，每一行号旁边挂着一份该行文本的隐形副本，
  高度由浏览器量，所以一行折成三行时号码也跟着占三行的高度
- **语法高亮**画在 textarea 底下的一层 `<pre>` 里，上面那层的文字设成透明。
  认 js/ts/json、css、html/xml、shell/ini/yaml/toml/conf、python/ruby、sql、markdown 几族。
  **输入法组字时这一层会让开**，候选文字照常可见
- **查找替换**：区分大小写 / 全字匹配 / 正则，当前命中会自己画一个框
  （textarea 的选区只在获得焦点时才画，而焦点得留在搜索框里，回车才能接着找下一个）
- **快捷键**：`Ctrl+S` 保存、`Ctrl+F` 查找、`Ctrl+G` 跳转到行、`Ctrl+/` 注释、
  `Ctrl+D` 复制当前行、`Ctrl+Shift+K` 删除当前行、`Alt+↑/↓` 上下移动行、
  `Tab` / `Shift+Tab` 缩进和反缩进（多行选中就整块缩进）、`Home` 先到首个非空白字符
- 回车保留上一行的缩进，`{`、`(`、`[` 会自动配对，选中一段再按引号是把它包起来而不是替换掉
- 状态栏说清楚行列、总行数、大小、换行符、缩进方式和语言；**CRLF 的文件存回去还是 CRLF**
- 自动换行、缩进方式（2 空格 / 4 空格 / Tab）、字号记在 `localStorage` 里，下次打开还是这套
- 改过没存的话，关闭时会拦一下
- 超过 150 KB 的文件进「轻量模式」：不上高亮，行号只按逻辑行算，
  换行开着的时候干脆把行号栏收起来 —— 与其给一列对不上的号码，不如不给

`.env` 里的相关项：

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `FILES_ENABLED` | `true` | 整个文件标签的开关 |
| `FILE_MAX_ENTRIES` | `1000` | 单个目录最多列多少条 |
| `FILE_EDIT_MAX_BYTES` | `524288` | 超过这个大小的文件只能下载，不能在线编辑 |
| `FILE_UPLOAD_MAX_BYTES` | `33554432` | 单次上传总大小上限（上传是放在内存里的，这也是内存开销） |
| `FILE_UPLOAD_MAX_FILES` | `200` | 单次上传的文件个数上限 |

> 谁能改：实例的主人和管理员，跟其它实例操作一个口子。所有写操作（上传 / 保存 / 新建 / 重命名 / 删除）
> 都进审计日志。

## 让服务被外网访问（内网穿透）

穿透由你手动配，面板负责的是把端口稳定地固定在一段连续区间里，并且在审批时告诉你要转发哪个。

`.env` 里的相关项：

| 变量 | 作用 |
| --- | --- |
| `PORT_POOL` | 实例领取主机端口的区间，默认 `20000-20200` |
| `BIND_ADDRESS` | Docker 在宿主机上绑定的地址。穿透客户端跑在同一台机器上时填 `127.0.0.1` 最安全 |
| `PUBLIC_HOST` | 审批时对外地址留空的话，用它拼默认值；逐条手填就用不上 |
| `PUBLIC_PORT_OFFSET` | 同上，只影响默认值的端口部分 |
| `PANEL_PUBLIC_URL` | **面板自己**在公网上的入口（例 `http://1.2.3.4:8099`）。静态站点走面板端口、不占端口池，所以站点地址跟着它走 |

> 静态站点显示成 `http://localhost:8099/s/xxx/`、外网打不开，就是 `PANEL_PUBLIC_URL` 没填。
> 面板端口本身也得先能从外网连上（穿透里除了端口池，别忘了把 8099 也转出去）。

两种用法，挑一种：

- **逐条手填（推荐，配合审批）**：审批时把该实例真实的对外地址填进去，
  这样每个实例可以有完全不同的域名或端口，面板照实显示。
- **整段转发 + 默认地址**：一次性把 `20000-20200` 全段映射出去、远端端口保持一致，
  再设 `PUBLIC_HOST=你的frps域名`，审批时地址栏留空即可自动拼出 `域名:主机端口`。

**frp 整段转发示例**（`frpc.toml`）：

```toml
serverAddr = "你的frps服务器"
serverPort = 7000
auth.token = "xxx"

[[proxies]]
name = "lh-pool"
type = "tcp"
localIP = "127.0.0.1"
localPort = "20000-20200"
remotePort = "20000-20200"

[[proxies]]
name = "lh-panel"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8099
remotePort = 8099
```

然后 `.env` 里写 `PUBLIC_HOST=你的frps服务器`、`BIND_ADDRESS=127.0.0.1`。
UDP 服务（比如某些游戏服）需要在 frp 里再加一段 `type = "udp"` 的同名端口范围。

其它工具同理：**cloudflared** 适合纯 HTTP 服务——审批时看到主机端口，加一条 ingress 规则
指向 `localhost:该端口`，再把分到的域名填进对外地址栏；
**ngrok / natapp** 免费版通常只给一个随机端口，只适合自己试玩。

## 手机上也能用

面板整套界面都按手机适配过：登录、建实例、审批、改文件、看日志、开控制台，在 320px 宽的屏幕上
都能完整走完，不需要缩放、不需要横向拖动。

CSS 里只有三条查询在管这件事，各管一个正交的问题（见 `public/style.css` 末尾那一节）：

| 查询 | 管什么 |
| --- | --- |
| `@media (max-width: 640px)` | **布局**：屏幕窄。全站唯一的布局断点，原来散落的三处 620px 已经并进来了 |
| `@media (pointer: coarse)` | **输入**：用手指点。触屏笔记本也吃这一套 —— 44px 点击区、16px 输入框 |
| `@media (max-height: 520px)` | **纵向空间**：横屏手机。屏幕够宽但没有高度，`vh` 和 sticky 都得让 |

手机上具体变了什么：

- **顶栏两行**：品牌 + 头像 + 退出 一行，五个入口一行（图标在上、文字在下、等分五格）。
  待审批数量做成角标贴在「管理后台」图标角上，不再占第三行。整条顶栏从 369px 降到 119px。
- **表格变卡片**：后台六张表 + 环境变量表 + 待审批的端口表，每一行变成一张卡，列名由表头自动
  贴到每个单元格上（`labelCards()`）。以前操作按钮在屏幕外 110px 处，管理员填不了「对外地址」，
  现在那个输入框是整行宽、16px 字号。
- **文件列表变两行**：文件名一行，大小/时间一行，四个操作按钮钉在右边 —— 以前它们全在横向
  滚动条外面。
- **点击区**：按钮至少 44px，密集行里的图标按钮 40×40 且彼此隔开 6px（删除不会紧贴重命名）。
- **输入框 16px**：低于 16px 时 iOS 一聚焦就把整页放大且不还原，这是表单最烦人的一个坑。
- **Toast 挪到顶部**且撑满宽度 —— 原来在右下角、宽 360px，手机上整条在屏幕外，所有成功/失败
  提示都白发了。
- **刘海和安全区**：`.shell`、顶栏、toast、向导底栏都按 `env(safe-area-inset-*)` 让位。
- **操作日志分页**：手机上先给 40 条，按「再看 40 条」继续 —— 200 条卡片是一屏 99000px 的东西。
- **控制台的按键条**：Esc / Ctrl+C / Ctrl+D / Ctrl+Z 一条横向滚动的按钮带，和命令行一起吸底。
  软键盘上没有这些键，而中断、退出全靠它们。软键盘的高度用 `visualViewport` 量出来写成
  `--kb`，终端主动让出那一段，所以输入行不会被键盘埋掉（`dvh` 不会因为键盘而变短，
  它是浮在上面的）。触屏上工具栏里的「中断/清屏」跟着收起来 —— 同一个动作不该在一屏出现两次。

几处刻意的取舍，不是漏掉的：

- 密集行里的图标按钮是 40px 而不是 44px（Apple 的建议是 44，Material 允许密集场景 40），
  否则一行文件要 60px 高。
- 宽度低于 420px 时隐藏用户名（头像有首字母，「账号」页有全名）、隐藏文件的修改时间列、
  「新建文件夹/新建文件」只留图标 —— 这些位置在 320px 上真的挤不下第二样东西。
- 641–1080px（平板竖屏那一档）沿用桌面布局，只是顶栏会折行。这一档没有专门优化，
  因为再加断点就会改变「把桌面窗口拖窄」时的表现。

改动只作用于窄屏和触屏：桌面端 1440px 下 11 个路由 84 个选择器的计算样式逐项比对过，
唯一的差异是地址胶囊（`.addr`）现在会在自己内部折行 —— 那本来是个 bug，长网址会冲出卡片 33px。

## 加一个模板

编辑 `src/templates.js`，往数组里追加一项，重启面板即可：

```js
{
  id: 'my-app',
  name: '我的应用',
  icon: '🚀',
  category: '工具',
  image: 'someone/my-app:latest',
  description: '一句话说明',
  ports: [{ container: 3000, protocol: 'tcp', label: 'Web' }],
  env: [
    { key: 'API_KEY', label: '密钥', type: 'password', required: true, generate: 'password' },
    { key: 'MODE', label: '模式', type: 'select', options: ['a', 'b'], default: 'a' },
  ],
  volumes: ['/data'],            // 会创建命名卷并挂到这些路径
  cmd: ['node', 'server.js'],    // 可选，覆盖镜像默认启动命令
  defaults: { memoryMb: 512, cpus: 0.5 },   // 只作为「建议券额度」展示，实际值由券决定
}
```

`generate: 'password'` 的字段用户留空时会自动生成强密码，创建后在实例详情页可见。

## 安全边界

面板给容器加了这些约束：内存 / CPU（NanoCpus）/ 进程数上限、`no-new-privileges`、
禁止 `--privileged`、禁止 host 网络、日志按 10MB×3 轮转、自定义镜像走仓库白名单且需管理员单独授权。

但**容器不是虚拟机**，root 容器逃逸风险始终存在。给不完全信任的人用时，请注意：

- 面板必须以能访问 Docker socket 的权限运行 —— 这等价于宿主机 root。别把面板暴露在没有认证的公网上。
- 强烈建议把整套东西跑在一台专用机器 / 虚拟机里，而不是你的主力开发机。
- 想再稳一点：给 Docker 配 `userns-remap` 或换用 gVisor / Kata 运行时。
- `DEFAULT_ALLOW_CUSTOM_IMAGE` 保持 `false`，只在个别资源券或个别账号上单独开自定义镜像权限。
- 文件管理和控制台一样，能力范围**就是容器内部**：用户本来就能在自己的容器里为所欲为，
  面板只是给了个网页界面。它不会碰宿主机路径 —— 读写都走容器自己的挂载命名空间。
  不想给这个界面就设 `FILES_ENABLED=false`（控制台仍然在，真要改文件的人绕得过去）。
- 磁盘配额（`DISK_QUOTA`）只在部分存储驱动（overlay2 + xfs prjquota 等）上生效，Docker Desktop 上会被忽略。
  Docker Desktop 环境下靠 `DISK_GUARD_ENABLED` / `DISK_QUOTA_MB` 兜底：面板定时查每个实例数据卷的实际占用，
  超过配额就自动停止该实例；不是内核硬限制，两次检查之间的突发写入仍可能短暂超额。

## 常见问题

**面板起来了但创建实例报错「无法连接 Docker」**
确认 Docker 正在运行。Windows 上面板默认走命名管道 `//./pipe/docker_engine`；
如果你的 Docker 监听在别处，在 `.env` 里设 `DOCKER_HOST=tcp://127.0.0.1:2375`。

**端口池已耗尽**
`PORT_POOL` 区间太小或被别的程序占用了。面板分配前会实测端口能否绑定，
Windows 上被 Hyper-V/WSL 保留的端口段（`netsh interface ipv4 show excludedportrange protocol=tcp`）会自动跳过。

**忘记管理员密码**

```bash
node scripts/reset-admin.js admin 新密码至少8位
```

**给升级前就存在的老账号补发见面礼**
见面礼只在注册那一刻发，所以升级到带这个功能的版本时，已有账号手上是空的。
补发（默认跳过管理员；反复跑不会重复发）：

```bash
node scripts/grant-welcome-vouchers.js         # 先看会发给谁，不写库
node scripts/grant-welcome-vouchers.js --yes   # 真的发
```

**休眠的实例访问不了 / 唤醒失败**
面板必须在运行 —— 休眠期间是面板替容器守着端口的。日志里如果出现「休眠后无法接管端口」，
说明那个端口被别的程序抢了，面板会把容器重新启动回去。

**开了休眠但它从来不睡**
判空闲看的是容器网卡收发字节。服务自己在定时对外通信（心跳、拉取更新、监控上报）就一直算活跃。
可以调大 `IDLE_MINUTES` 没用，得先把那类后台流量关掉。

**用户手动删了容器 / 面板重启后状态对不上**
面板启动时会和 Docker 对账；容器不存在的实例会标成「容器丢失」。
管理后台还有个 `/api/admin/orphans` 接口可以列出面板已经不认识的托管容器。
